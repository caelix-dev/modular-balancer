# modular-balancer

Factorio 2.1.23 mod, published on the mod portal as `modular-balancer` (current version in `info.json`). Parent workspace rules in `../CLAUDE.md` apply. Player-facing behaviour is described in `README.md`; keep it in step with the code.

## Constraints

- Factorio 2.1.23 only. `info.json` `factorio_version` is `"2.1"`.
- Before writing mod code, read `../factorio-dev/spec/MODDING-RULES.md` and look every API name up in `../factorio-dev/spec/api/2.1.23/` (runtime-api.json, prototype-api.json). Do not rely on memory.
- Test with fdev (below). Never launch the game by hand.
- FactorioTest suites use plain `assert(cond, "message")`, never luassert.
- Never touch `E:\SteamLibrary\steamapps\common\Factorio` or `%APPDATA%\Factorio`. Never print or commit the token in `%USERPROFILE%\.config\factorio-dev\credentials.json`.
- Plain hand-written Lua, no transpiled runtime. Multiplayer-safe: persistent state only in `storage`, nothing but the three legitimate uses in `on_load`.
- No per-tick or per-item script work in the steady state. Script runs only on build/change events.
- Never lose or duplicate items.
- Git remote: `origin` (GitHub, `caelix-dev/modular-balancer`). Work on a branch and merge into `main`. A version bump is released in the same job without asking (see Releases); any other push needs the user's approval.
- Prototype names are prefixed `mb-`.

## Test commands

Run from the repo root unless noted.

- Offline unit tests: `..\.tools\lua52\lua52.exe tests/unit/run.lua`
- Static check (from `C:\Users\shimj\Documents\factorio`): `factorio-dev\target\release\fdev.exe lua check modular-balancer`
- In-game tests (same directory): `factorio-dev\target\release\fdev.exe test modular-balancer --timeout-secs 1800 [--preset vanilla|space-age]`. Always pass `--timeout-secs`: a vanilla run takes about 8 minutes alone and longer when other runs share the machine, and fdev's default timeout (600 s) kills it with no test result. fdev has 4 test slots; retry when they are busy.

Unit test contract: each `tests/unit/*_test.lua` returns `{ [name] = function() ... end }`; `run.lua` runs them in sorted order and exits non-zero on any failure.

## Releases

Every version bump is published to the mod portal as part of the same job:

1. Run the static check, the offline tests and both game presets.
2. Bump `info.json` `version`, add a `changelog.txt` entry (Factorio changelog format), and update the version line in `README.md`.
3. Commit, merge into `main`, tag `vX.Y.Z` and push the branch and the tag.
4. Build the zip with `git archive --prefix=modular-balancer_X.Y.Z/ -o modular-balancer_X.Y.Z.zip vX.Y.Z` (committed files only, never the working tree).
5. Upload it with the portal API key in `%USERPROFILE%\.config\factorio-dev\portal-api-key` (never print it): `POST https://mods.factorio.com/api/v2/mods/releases/init_upload`, then POST the zip to the returned `upload_url`.
6. Check the release list at `https://mods.factorio.com/api/mods/modular-balancer`.

`.gitattributes` export-ignores `spikes/`, `tests/`, `bench/`, `docs/`, `tools/`, `.emmyrc.json`, `.superpowers/`, `scripts/flow.lua` (test-only) and this file, so a release has no test code, no spikes, no render tooling and no dev marker (`tests/dev.lua`): the dev gate `mb-dev` is then off even for a player who has `factorio-test` enabled. Check with `git archive HEAD | tar -t` before shipping.

## File map

- `info.json`, `settings.lua`, `data.lua`, `data-final-fixes.lua`, `control.lua` - mod entry points (`data-final-fixes.lua` builds the hidden prototypes). `control.lua` has the mod's only `on_init` and `on_configuration_changed` handlers (each can be registered once); later code adds its work to them instead of registering again. `control.lua` hooks FactorioTest when the dev gate `mb-dev` is on; add new suites to its list.
- `settings.lua` - two hidden, forced startup settings: `mb-dev` (on only with `factorio-test` enabled and the committed, export-ignored marker `tests/dev.lua`) gates every piece of test code (`tests/game/data.lua`, `tests/game/remote.lua`, the suites); `mb-spikes` (needs `mb-dev` and the git-ignored `spikes/local-enable.lua`) gates the spikes.
- `prototypes/hidden.lua` - hidden per-tier entities of the balancing network (`mb-hidden-splitter-<tier>`, also the priority splitter, `mb-hidden-linked-belt-<tier>`, `mb-hidden-lane-splitter-<tier>`, `mb-hidden-loader-<tier>`), the buffer chest `mb-hidden-buffer` and the dead-end filter item `mb-hidden-never`, and the edges `mb-edge-in|out-<belt>` (the belt's look; a fast-replace group of their own, so a belt drag across an edge goes under it, and only a line dragged along it in its direction replaces it via `on_pre_build`; hidden, so no planner lists or selects them) with their animations `mb-edge-belt-<belt>-<direction>[-odd]` (the half tile a linked belt leaves blank, drawn by `scripts/io.lua`); required from `data-final-fixes.lua`. The turbo tier exists even without Space Age (express copies at turbo speed), so a save that drops Space Age keeps its turbo networks' items.
- `prototypes/blocks.lua` - the visible blocks `mb-balancer-<tier>` (entity `simple-entity-with-owner` with the F1 block mask, item, recipe, unlock by the tier's splitter technology, upgrade chain, Blender-rendered sprites in `graphics/entity/balancer/hr|lr/` (set chosen in `prototypes/gfx.lua`; entity `animations`: one per neighbourhood (47), each the static frame held with `repeat_count`, the shared 16-frame machinery loop and the shadow, so the block animates with no script; the port housings are the edges' structure in `prototypes/hidden.lua`); without Space Age the turbo block and item exist hidden, with no recipe); required from `data.lua`. `locale/en`, `locale/ko` - same keys in both.
- `scripts/groups.lua` - connected groups of same-tier, same-force blocks (`storage.groups`; merge and split on every build/remove, re-key on `on_forces_merged`; each change returns `ids, gone`). `scripts/events.lua` - registers every build/remove/rotate/flip/paste/force-merge event (name filters for blocks, type filters for belt-connectables and inserters, `register_on_object_destroyed` for blocks); the only place these events are registered. Handlers only mark groups dirty (`scripts/balancer.lua`), so bulk changes refresh each group once per batch.
- `scripts/io.lua` - ports of a group (F1, F3, F4): `scan` finds edges, shared tiles, block-tile interfaces and inserter ports (with refusals); `swap`/`unswap` turn a belt tile into an edge `mb-edge-in|out-<belt>` and back, keeping items; `dress` draws an edge's missing half tile (a render object owned by the edge), `dress_all` on configuration changes; `block_port` places the linked belt on a block tile (F3 facing rule); `give_back` undoes a belt built on a block tile, or a block built on a belt that is not marked for deconstruction. `scripts/balancer.lua` - live balancing: events mark groups dirty, an `on_nth_tick(1)` handler (registered only while something is dirty, re-set in `on_load`) flushes them once per batch: retire gone groups (networks to the merging group or spilled), scan, swap, build a network when the group has none and rebuild it when N or M changed or the group's settings differ from the network's (networks merged in drain into the working one), link ports and shared tiles, swap unclaimed edges back. Work per tick is bounded (`balancer.tick_budget` work units, `builder.COST`): rebuilds are staged jobs in `storage` (generate, in a tick of its own above 16 ports per side; place over ticks while the old network runs; then switch over and drain the sealed old networks into the new one item by item; a drain that finds the new buffer full is "stuck" (`st.stuck`, refusal `drain-stuck`) and retried by an `on_nth_tick(300)` handler registered exactly while `st.stuck` is non-empty, also re-set in `on_load`), removed networks are taken out and spilled over ticks (`spill_queue`), and groups or edge unswaps over the budget wait for the next tick; the handler stays registered while any of this remains (`balancer.pending`). Both conditional handlers are set only through `set_flush_handler` / `set_stuck_handler`, which keep the test mirror `balancer.registered`; `balancer.spent` is the units the last budgeted flush charged (tests). `balancer.flush()` without a budget does everything at once (tests); `balancer.after_flush` is the GUI hook. `balancer.drop_networks` (the hidden surface about to go) is unbounded on purpose.
- `scripts/lifecycle.lua` - blueprints and copy-paste (`on_player_setup_blueprint` rewrites edges to the belts they replaced), edge ghosts (become belt ghosts), undo/redo (`on_undo_applied`), the upgrade planner (an edge next to a belt-connectable of its tier marked for upgrade is swapped back and its belt gets the order; an order targeting an edge is redirected to its belt), drag along an edge (`on_pre_build` / `pre_build` swaps an edge of the player's force back to its belt before a build from an item cursor facing the edge's direction, so a line dragged along it replaces it like vanilla; a build across or against it is left alone and smart belt building goes under it; measured with a real player 2026-10-30), configuration changes (blocks of a tier whose belt is gone, turbo after Space Age is removed, are replaced by the fastest tier left with their items; a lost hidden surface is replaced) and the hidden surface deleted or cleared at runtime (networks spilled first, then placed again). Edges built by the game (not by the mod) are "loose" in `scripts/balancer.lua` until a group claims them; a block's network goes to whoever mined its last block (`balancer.give`).
- `scripts/gui.lua` - per-balancer settings (Plan 3 Task 3) and the per-block filter part of the frame, laid out as an inserter's (Use filters, five `choose-elem-button` slots, the Whitelist/Blacklist switch with vanilla captions, Per lane; `on_gui_elem_changed`, `on_gui_switch_state_changed`; Use filters off disables the rest; per lane shows two slots and locks the switch and Balance lanes, values kept): balance lanes and redistribute unused shares, stored on the group (on a block ghost: tags on its connected ghost cluster, `gui.ghost_cluster`, plus any built group it touches; the frame follows the ghost to its block via `storage.mb_gui.where`) (`scripts/groups.lua`: a merge keeps the larger group's, a split copies them); the settings frame opened by clicking a block (linked custom inputs in `prototypes/inputs.lua`, since a simple-entity-with-owner has no GUI), settings paste (`on_entity_settings_pasted` and the copy/paste-entity-settings controls), blueprint tags `mb_lanes` / `mb_recirc` (written from `lifecycle.on_player_setup_blueprint`, read on build in `scripts/events.lua`). A change marks the group; the flush rebuilds when the settings differ from the network's (`rec.lanes`, `rec.recirc`); `gui.after_flush` (the `balancer.after_flush` hook) sets a refused rebuild's settings back and re-checks open frames. Open and paste follow one rule (`gui.can_use`: own force, in reach or remote view) and the permission group; frames close when their block goes or is out of reach; GUI state is cleared on player leave/removal. The `mb-test` remote functions `input`, `click`, `setup_blueprint`, `info`, `gui_info` drive the handlers for a connected player (F11). `gui.lookup_player` (game.get_player) lets headless tests use a stand-in player. Tests: `tests/game/lanes.lua`.
- `prototypes/tips.lua` - the Tips and tricks category `modular-balancer` and its entries, each with a simulation (`mods = {"modular-balancer"}`, so the real mod runs in it; `init_update_count` per scene from `warmup`: the measured time for its new networks of yellow belts to fill and its rates (exact 10 s window) to settle, 1500 to 3000 ticks; the game pauses for these ticks when a tip opens, so keep them short). `prototypes/tips_scenes.lua` holds the scenes as pure data: a shared helper prepended to every scene's init and to the update (simulation code is a console command, no `require`): basic (yellow) belts, blocks built from ghosts with blueprint tags (`mb_lanes`, `mb_recirc`, `mb_filter`) and revived with `raise_revive`, sources that keep a belt full (each lane takes the items in turn), sinks that clear the last belt and label each lane's items per second. The helper leaves its update in the console global `mbsim_update`; the per-tick update only calls it (compiling the helper every tick took about two thirds of the update time). To try a scene on an MCP instance (needs `factorio-test` for the dev gate): `remote.call("mb-test", "tips_code", name)` returns `{init, update}`; run `load(init)()` on a lab-tiled area of surface 1 and the update from an `on_tick` handler. Unregister that handler before `gui_connect`: a console-registered handler is not saved and the client refuses to join.
- `scripts/look.lua` - connected look: the 47 neighbourhood masks (same order as the sprite sheets), and `dress`, which sets each block's `graphics_variation`; called at the end of `balancer.flush` next to `after_flush`, for the groups refreshed or whose staged rebuild completed (no per-tick work). Tests: `tests/unit/look_test.lua`, `tests/game/look.lua`.
- `tools/render/` - the sprite pipeline: `scene.py` models and renders in Blender (`E:\Blender\blender-5.2.3-windows-x64\blender.exe -b --factory-startup --python tools/render/scene.py`; raw renders in the git-ignored `tools/render/out/`) the block per neighbourhood and tier, its shadow, the machinery loops and the port housings; `tiers.json` holds the tier paint colours, started from the lit paint of the vanilla splitter and underground sprites by `calibrate.py`, then judged by eye in game; `pack.py` (Pillow) builds the HR and LR sheets and the icons; `preview_gif.py` makes review GIFs. `docs/plan3/build-scene.lua`, `tidy-scene.lua` - screenshot scenes for an MCP instance.
- `scripts/filters.lua` - per-block item filters (pure Lua): the record kept on the block (`scripts/groups.lua` block record `filter`; blueprint and ghost tag `mb_filter`), `effective` (what it does, items of removed mods dropped), `signature` (part of a rebuild's shape: `rec.fsig`, `job_key`). `scripts/balancer.lua` hands every output port its block's filter to `network.build` (`opts.filters`). `scripts/events.lua` gives a built block its filter from the tags, a clone's source, or the block it replaces on the same tile (upgrade: `storage.mb_carry` for the tick, fast replace: the stale record). `scripts/badge.lua` draws a block's filter items in alt mode (render objects on the block, kept on its record as `badge`, redrawn when the filter changes or the block is built). Tests: `tests/unit/filter_test.lua` (routing of filtered networks), `tests/game/filter.lua`.
- `scripts/network.lua` - network generator (pure Lua); with filters a filtered network (filter-splitter chain per input, a base network per class of items with the same outputs, merge trees, filtering lane splitters for per-lane outputs; see `filtered()`). `scripts/builder.lua` places filter splitters (`filter`/`prio`, never closed) and a filtered network drains into its buffer only (`placed.buffer_only`), so carried items pass the filters. `scripts/flow.lua` - offline flow model, never required by product code (only test code: `tests/unit`, and `tests/game/exactness.lua`).
- `scripts/surface.lua` - the hidden surface `mb-hidden` and its region allocator (best fit, split, freed regions joined; pure `alloc`/`free`, tested offline in `tests/unit/allocator_test.lua`). `scripts/builder.lua` - places a network on it over budgeted calls, all or nothing (`start`/`advance`/`abort`; every hidden entity indestructible), `contents`, `destroy`, `seal`/`drain`/`settle` (the staged carry), `take` (optionally within a budget), `stash`, `compact`. There is no synchronous place or rebuild in product code; test code uses `H.place` and `H.rebuild_net` in `tests/game/harness.lua` (the same primitives without a budget).
- `tests/unit/` - offline tests and `run.lua` runner.
- `tests/game/` - FactorioTest suites run by `fdev test` (`placement.lua`, `exactness.lua`, `rebuild.lua`, `groups.lua`, `io.lua`, `play.lua` (live balancing end to end), `lifecycle.lua` (blueprints, undo, ghosts, upgrades, configuration), `lanes.lua`, `filter.lua` (item filters), `look.lua` (connected look), `staged.lua` (bounded work per tick, `rebuild_cost_is_bounded`, stuck drains, handler registration checked against storage on every tick, eggs on the hidden surface, a platform as the visible side, two forces), shared rig `harness.lua`, which also has `H.place` / `H.rebuild_net`). `tests/mods/mb-test-speed` is a test-only mod for the tier-speed MCP check (F9). Loaded only with the dev gate `mb-dev`: `data.lua` (harness prototypes `mb-test-*`) and `remote.lua` (remote interface `mb-test` for the F6 and groups save/load checks and the F7 benchmark saves on an MCP instance).
- `spikes/` - throwaway research spikes, loaded (prototypes and test suites) only when the hidden startup setting `mb-spikes` is on. It is forced on only when the git-ignored `spikes/local-enable.lua` exists (`return true`, or `return { variant = "<name>" }` for a prototype variant) and `mb-dev` is on; otherwise forced off. An MCP `server_start` instance without `factorio-test` therefore has no spike prototypes. `spikes/multi_belt/repro-load-errors.sh` reproduces the prototype-stage errors of F1. `spikes/hidden_surface/save_load.lua` registers the remote interface `mb-spike-s2` (only with `mb-spikes`) for the F2 save/load check on an MCP instance.
- `docs/feasibility.md` - spike findings (F1..), screenshots in `docs/feasibility/`.
- `bench/` - UPS gate benchmark tooling (Plan 3 Task 1): `builders.lua` (save builders, remote functions `bench_*` of `mb-test`, loaded by `tests/game/remote.lua` behind the dev gate), `ticklens.sh`, `summarize.py`, `tables.py` (round 1), `tables2.py` (round 2), `bench_edge_probe` (edge-join probe), `bench_staged` / `bench_items` / `bench_phases` / `bench_eval` (Task 5 staged rebuild hitch). Results in `docs/benchmarks.md` and `docs/benchmarks/raw/`.
- `.emmyrc.json` - editor config (FactorioTest globals whitelisted). `fdev lua check` ignores it and generates its own.
- `.superpowers/` - local planning notes, git-ignored.
